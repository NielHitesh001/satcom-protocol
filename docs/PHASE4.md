## 1. Methodology

### Data classes (must not be confused)

| Class | Description |
|-------|-------------|
| **sample TLE** | `data/starlink_sample.tle` — small repo sample, Starlink-*style*, **not** full constellation |
| **synthetic Walker** | Generated by `constellation.generate_walker_tles` — **synthetic only**, for scaling studies |

All Phase 4 scale numbers below use **synthetic Walker** TLEs unless noted.

### Tools

| Script | Purpose |
|--------|---------|
| `experiments/scale_profile.py` | Subsystem timing: load, propagate, topology |
| `experiments/full_scale_sim.py` | End-to-end routing on synthetic constellations |
| `experiments/stats_summary.py` | Mean / std / normal-approx 95% CI from CSV |
| `scripts/bench_topology.py` | Spatial vs brute (random ECEF shells) |

### Topology-only profile settings

- Duration 60 s, time step 15 s → **5 epochs** for N≤200 table  
- max_range = 3000 km  
- Spatial index forced on for large N; brute compared only for N≤200

## 3. Full routing simulation (synthetic Walker, max_range=5000 km)

| Protocol | N | Seeds | Delivery (mean) | Control (mean) | Wall mean |
|----------|--:|------:|----------------:|---------------:|----------:|
| predictive | 50 | 42–44 | 1.000 | 0 | ~0.52 s |
| aodv | 50 | 42–44 | 1.000 | 740 | ~0.46 s |
| predictive | 20 | 42 | 0.000 | 0 | ~0.5 s |
| aodv | 20 | 42 | 0.000 | 11 | ~0.4 s |

At N=20 the chosen endpoints were not connected under the generated geometry/range — delivery 0 is a topology outcome, not metric corruption. Packet conservation held where metrics were emitted.

**95% CI (normal approximation, n=3 seeds, N=50 predictive):** delivery mean 1.0 (degenerate std 0); wall CI approx [0.42, 0.61] s. Small-n CIs are rough — documented as such in `stats_summary.py`.

## 4. Spatial index conclusions

- Equivalence to brute force retained at N=80 (test) and in profile runs ≤200.  
- Candidate counts ≪ N² (e.g. N=200 → 3066 candidates vs 19900 pairs).  
- On 1.3 GB RAM host, N=2000 topology snapshot completed (~2.6 s wall, ~118 MB RSS).  
- No CSR rewrite was required for Phase 4 measured sizes; `edge_index` dict already provides O(1) link param lookup.

---

## 5. Orbital propagation conclusions

- Precomputed JD/GMST grid remains in place from Phase 3.  
- Bottleneck for large **T** is sequential SGP4 calls (library constraint).  
- No approximate propagator was substituted.  
- Outputs validated via existing geometry tests + new Walker load/propagate test.

## 8. Remaining bottlenecks

1. Sequential SGP4 for large N×T  
2. Full OLSR control cost at dense graphs (event volume)  
3. Host RAM (1.3 GB) limits concurrent large full-stack runs  
4. Synthetic Walker is **not** Starlink operational fidelity  
5. Endpoint selection for traffic should be connectivity-aware in future work
